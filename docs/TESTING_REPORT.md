# Отчёт о тестировании

## 1. Цель тестирования

Цель тестирования — подтвердить, что pipeline запускается, создаёт основные выходные файлы, корректно обрабатывает заголовки, фразовые маркеры, шумовые случаи, metadata и отчёты качества.

## 2. Команда запуска тестов

```bat
pytest -q
```

Фактический результат финальной версии:

```text
2 passed
```

## 3. Что проверяется

Тесты проверяют:

1. Создание `MARKERS_MASTER.csv`.
2. Создание `SENTS.csv`.
3. Создание `HEADINGS.csv`.
4. Исключение заголовков из аналитических предложений.
5. Создание `TD_HITS_TAGGED.csv`.
6. Создание `STATS.xlsx`.
7. Создание `SHOWCASE.xlsx`.
8. Создание `PHRASE_QUALITY_REPORT.xlsx`.
9. Создание `QUALITY_DASHBOARD.xlsx`.
10. Создание `MANUAL_VERIFICATION.xlsx`.
11. Создание ключевых графиков.
12. Наличие `phrase_family`.
13. Наличие уровней `CORE` и `EXTENDED`.
14. Исключение WORD внутри PHRASE из основного счёта.
15. Распознавание `Подумаешь` как шумового случая.
16. Синхронизацию `RUN_METADATA.json` и `STATS.xlsx`.
17. Отсутствие временной папки после `validate_project`.

## 4. Ограничение тестов

Текущие тесты являются smoke/quality-тестами. Они подтверждают работоспособность pipeline и ключевые правила учёта. Для промышленного уровня можно дополнительно добавить unit-тесты на каждую функцию речевой атрибуции, но для дипломного проекта текущий уровень тестирования достаточен и объясним.
